# Directive Soft Delete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clearing finished directive runs marks them deleted instead of destroying them, and the same click hard-deletes any terminal run finished more than a month ago.

**Architecture:** One nullable `deletedAt` column on `directives` carries the mark. `DirectiveResolutionClient.clearFinished` becomes two operations in one transaction — mark, then purge — both restricted to `.completed`/`.cancelled`. The Directives list filters marked rows out of its query; nothing else in the app reads terminal directives, so the engine is untouched. `DirectiveLogRetention.window` widens from 7 days to 30 so a kept row's timeline outlives the same clock.

**Tech Stack:** Swift 6 / SwiftPM package at `app/Modules`, SQLiteData + StructuredQueries over GRDB, Point-Free Dependencies, ComposableArchitecture, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-08-10-directive-soft-delete-design.md`

## Global Constraints

- **Migrations are append-only.** A new column means a new `SchemaMigration` appended to the END of `GameDatabase.manifest` and to the END of `SchemaManifestTests.frozenIdentifiers`. Never edit, rename, or reorder a shipped migration — GRDB keys applied migrations by identifier, so an edit silently never runs.
- **Terminal statuses only.** Every write in this plan is restricted to `DirectiveResolutionClient.finishedStatuses` (`.completed`, `.cancelled`). `.running`, `.needsAttention` and `.paused` still own devices via `Brain.owningStatuses`; touching one releases its carrier to the brain mid-flight.
- **Comment budget is hard:** file header ≤ 6 lines, `///` doc ≤ 3 lines, inline `//` ≤ 2 lines. No dated history, no rejected alternatives, no rationale — those go to `app/.claude/memory/`.
- **Logging:** `os.Logger` only, subsystem `name.pennig.replicould`, category = the module name (`DirectiveEngine`, `GameSync`, `Directives`).
- **Read test results from the event stream**, never by grepping console text. Every run in this plan pins `--test-product` and `--event-stream-version 0`.
- **Never write `updatedAt` when marking a row deleted.** It is the purge clock; writing it would silently convert "finished over a month ago" into "deleted over a month ago".
- All `swift` commands run from `app/Modules` (where `Package.swift` lives).

- [ ] **Step 5: Add the purge to the closure.** Replace the `clearFinished` body written in Task 2 with:

```swift
        clearFinished: {
            @Dependency(\.defaultDatabase) var database
            @Dependency(\.date) var date
            let now = date.now
            let cutoff = now.addingTimeInterval(-purgeWindow)
            do {
                return try await database.write { db in
                    let unmarked = Directive.where {
                        $0.status.in(Array(finishedStatuses)) && $0.deletedAt.is(nil)
                    }
                    let marked = try unmarked.fetchAll(db).count
                    if marked > 0 {
                        // Deliberately not `updatedAt`: that column is the purge
                        // clock, and re-stamping it would restart the month.
                        try unmarked.update { $0.deletedAt = #bind(now) }.execute(db)
                        logger.info("marked \(marked) finished directive(s) cleared")
                    }
                    let doomed = try Directive
                        .where { $0.status.in(Array(finishedStatuses)) && $0.updatedAt < cutoff }
                        .fetchAll(db)
                        .map(\.id)
                    if !doomed.isEmpty {
                        // Entries first, then the rows they point at, in ONE
                        // transaction — every timeline query is keyed by
                        // directive id, so an orphan entry is unreachable.
                        let scoped = doomed.map(Optional.some)
                        try DirectiveLogEntry.where { $0.directiveID.in(scoped) }.delete().execute(db)
                        try Directive.where { $0.id.in(doomed) }.delete().execute(db)
                        logger.info("purged \(doomed.count) directive(s) past the retention window")
                    }
                    return marked
                }
            } catch {
                logger.error("clear finished failed: \(error)")
                return 0
            }
        }
```

## Notes for the implementer

**Nothing here changes what the engine sees.** Completed rows already sit in the database until someone clicks Clear — the mark only removes them from one SwiftUI query. If a task tempts you to filter `deletedAt` anywhere in `DirectiveEngine`, `GameSync`, or `GameServices`, stop: that would be a behaviour change nobody asked for.

**The migration is the one irreversible step.** Once `Add 'deletedAt' to 'directives'` has run against the live database at `app/.claude/memory/sqlite-db-location.md`, its identifier is recorded there forever. Editing it afterwards means it silently never runs again.
