SSE Event Log: a Raw-API-style diagnostic that persists **every** dispatched event and shows its full envelope in the shared JSON tree. Built 2026-07-20.

- **Capture point:** `EventLogClient.record` (GameServices) is called from `EventRouter.dispatch` in `GameSync/Sources/EventRoute.swift` — the single choke point. `isHandled = hasSpecificRoute || event.deviceCode != nil` (exact inverse of the existing "⚠️ UNHANDLED" rule). `testValue`/`previewValue` are no-ops so routing tests aren't touched.
- **Table:** `EventLog` (`GameModels/Sources/EventLog.swift`), PK = stream id (upsert dedupes catch-up vs stream), typed metadata columns + `payload` JSONValue blob. `EventLog.envelopeJSON` folds columns+payload back into one object for the detail tree. Registered in `GameDatabase.migrator()`. NOT cleared on logout (user-managed; clear via window button).
- **Module:** `EventLogFeature` — `EventLogView` (2-col split), list/row/detail, `@FetchAll` reloaded via `state.$events.load(query)` for the "unhandled only" filter. Hosted in its own window (Tools ▸ Event Log, ⌥⌘E) scoped through `MainFeature.eventLog`, mirroring `RawAPIWindow`.
- **The ledger query MUST stay capped — `EventLogFeature.displayLimit` (1000).** On 2026-07-30 the app died with `AttributeGraph precondition failure: exhausted data space` (SIGABRT) after 5½h uptime. Cause: `@FetchAll(EventLog.order { $0.receivedAt.desc() })` was unbounded, and `SelectableList` is **not virtualized** — it is `ScrollView { LazyVStack { ForEach } }`, and a `LazyVStack` must measure its rows to size the scroll view, so it allocates AttributeGraph nodes for every row. `eventLogs` is written by the stream and **never pruned** (15,839 rows over 4 days at ~400–660/hour), so the graph grew until AG aborted mid-layout — the backtrace is pure layout (`ScrollViewLayoutComputer` → `LazyVStackLayout` → `measureEstimates` → `ForEachState.forEachItem` → `Node::allocate_value`), no update loop involved. **The filter reload must carry the same `.limit`**, or toggling "unhandled only" silently re-opens the unbounded fetch. Two consequences worth knowing: the table still grows (only the *query* is bounded — see [[operations-table-retention]] for the pruning precedent), and **any other `SelectableList` over an unbounded table has the same latent bug** (`stars` is already at 14,122 rows).
- **The SAME window died a SECOND time, 2026-08-10, in a different view — the detail tree, not the ledger list.** `AttributeGraph precondition failure: exhausted data space` (SIGABRT) after 13.5 h uptime. Cause: `JSONTreeNode.id` was `let id = UUID()`, a stored property minting a fresh id per instance, and `EventLogDetailView` builds the root **inside `body`** (`JSONTreeView(node: JSONTreeNode(value: event.envelopeJSON))`), so every body evaluation re-identified the entire tree. `selectedEvent` derives from the `@FetchAll` `events`, which reloads on **every SSE insert** (measured 1–9/min), so with an event selected the whole tree was torn down and rebuilt with new identities every few seconds all session. Fixed by deriving `id` from the node's **ordinal path** (`"0"`, `"0.3"`, `"0.3.1"`) so an equal value rebuilds to equal ids; `JSONExpansionStore.overrides` and `JSONFlatRow.RowID` re-key to `String`. **The ten-second field diagnostic:** collapse a node and wait for an event — `overrides` is keyed by node id, so if the ids are being reminted the node springs back open. Three things worth keeping: (1) **the two lazy stacks are told apart by the frames between the stack and its ScrollView** — `JSONTreeView`'s is `LazyVStackLayout → _FlexFrameLayout → _PaddingLayout → ScrollViewUtilities`, while `SelectableList` puts its `LazyVStack` *directly* in the `ScrollView` with nothing between; (2) **the AG data arena that aborts is ~1 MB**, so `vmmap`'s `AttributeGraph Data` region says nothing about severity — the graph's real size is the `AttributeGraph graph data` **malloc zone** (828,737 live allocations / 209.8 MB here, against 29,087,077 / 5.2 GB in `DefaultMallocZone` and a 7.0 GB footprint), and RSS is a co-symptom, not the thing that aborts; (3) **`heap` and `leaks` cannot census this process at all** — an empty registered `AttributeGraph_0x…` zone fails malloc enumeration and `heap` treats any unenumerable zone as fatal with no skip flag, `--forkCorpse` included, so `vmmap`'s per-zone table (which needs no object walk) is the only census available. **The first cut of that fix REGRESSED, and the lesson generalises: the UUID was doing two jobs, and only one of them was the bug.** Ids derived from position alone are identical across structurally-similar documents, and `JSONTreeView` owns `@State private var expansion = JSONExpansionStore()` which SwiftUI keeps alive when only the `node` changes — so collapsing `payload` on one event collapsed it on every event selected afterwards. The per-render UUIDs had been supplying a fresh keyspace per *document* as a side effect of supplying one per *render*; removing the churn removed the isolation with it. Fixed by naming the document: `JSONTreeNode.init(documentID:value:)` is REQUIRED (no default — a default constant collides exactly like `"0"` did, and the compiler asking every call site is the whole point), the root id IS the document id, and children extend it. Call sites pass `event.id` (Event Log) and `RequestHistoryItem.id` (Raw API, threaded through a new `ResponsePaneFeature.State.responseID` — note `CapturedResponse.asResponse` is COMPUTED, so a `UUID` stored on `Response` would be reminted per access and reintroduce the churn). Still open: `JSONTreeView.initiallyExpanded = true` means a tree starts fully expanded, so the largest live envelope (an `ami.survey.digest` at 897 JSON nodes) still materializes every row in one measurement pass.
- **JSONTreeView is now shared from the `UI` module** (moved out of RawAPIFeature; `UI` gained a `Utils` dep). `JSONTreeView`/`JSONTreeNode` are public. Reuse it anywhere: `JSONTreeView(node: JSONTreeNode(value: someJSONValue))`. See [[event-stream-migration]], [[monospace-system-names]].
