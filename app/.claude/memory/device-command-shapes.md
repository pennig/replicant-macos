Probed live (2026-06-28) — `POST devices/{code}` returns one `DeviceCommandResponseSchema` (a big optional bag, `additionalProperties:true`). The completion *class* is read from which fields come back, not from a per-command schema:

- **travel** — self-describing: carries `arrives_at` → op `active` + `completesAt`. Completion event `device_cruise_arrived`.
- **start_mining** (`mine`) — **continuous**: response `{status:"mining_started", cycle_time_seconds}`. `cycle_time_seconds` is **per-cycle, not a completion ETA**. Op is `active` with `completesAt == nil`. Mining runs cycle-by-cycle until the **site depletes** (relay `site_resource_depleted`, now in `Reconciler.completionEventTypes`) or it's recalled — then the device read shows `idle`. While mining, `cycle_time_seconds` + `startedAt` extrapolate the current cycle; a high-priority poll-per-cycle (when viewing the drone) surfaces `pending_cycles`/`pending_quantity`. **There is no cargo-full completion** — drones never fill up; mined yield accumulates into the *location's* inventory with no upper bound. So the only mining terminators are `site_resource_depleted`, recall, or `deactivate`.
- **system_scan** (`scan`) / **stellar_census** (`census`) — **synchronous reads**: full data returned inline, no deadline, no completion event. They create **no tracked Operation** (op-less dispatch + one device read).
- **enqueue_print** (`print`) — enqueued; completes via `print_complete` (carries `new_device_code`).
- **retarget** — **continuous modifier**: `{status:"mining_retargeted", new_resource, old_resource}`, no deadline. Changes the *existing* mining op's resource in place → dispatched immediate (no new op). Server-gated: rejects unless mining (`"Device is not mining"`) AND the resource exists at the current site (`"No X remaining at this site"`). UI gates the button on status containing `mining`.
- **recall** — **deadline (self-describing)**, NOT status-only: cruises the device **home to stow on the nearest craft**, returns `arrives_at`. Tracked like travel; supersede ends any in-flight op.
- **stow** — status-only/immediate `{status:"stowed", stowed_in}`, optional `target` carrier (auto-picks nearest if omitted). Terminating. `deploy` is the inverse (`{status:"deployed", deployed_from, location}`).
- **deactivate** — the **in-place mining stop**: `{deactivated:"mining", status:"mining_stopped"}` → device back to `idle`, no relocation. There is **no `stop_mining` verb** (server 400 "Unknown command"). Terminating.
- **compact** / **unfurl** — **deadline (self-describing)**, despite being no-param. `compact` packs a device down for transport; `unfurl` is the inverse (expand back). POST returns `{completes_at, device_code, status:"compacting"|...}` and the device carries a matching activity block keyed by the command verb (`compact`/`unfurl`) with `{completes_at, eta_seconds, progress_percent, started_at}`. Wired 2026-07-09 as tracked deadline ops (block key + shape **confirmed live** by the user): added to `deadlineCommands`, `OperationKind.compact`/`.unfurl`, and both `Device.activityDeadline` + `Device.derivedActivity`. Generic active-task card + `OperationProgressView` render them for free; completed via settled-device path / DeadlineScheduler.
- **no-param lifecycle** (decommission/clear_queue/activate/…) — status-only/immediate, no op. `deactivate`/`decommission` terminating.
- **attach / detach** — immediate topology change on a carrier with the `attach` feature (e.g. `surge_plate`, which has `attach_capacity` + an `attached_devices` tail array). Both ship device codes under **`targets`** (a list), **not** `devices` like adopt/release — docs are the source of truth; the shared `devicesSchema` helper takes a `key:` param for this. Attach targets must be at the carrier's location; detach targets are the carrier's currently-attached devices. Carriers come in `attach_capacity` 1/4/9. The UI adapts on capacity: attach with 1 free slot → `.deviceChoice` dropdown, >1 free → `.multiSelect` capped at remaining slots (counter + Select-All), 0 free → `.notice("Carrier at capacity")` with confirm disabled (command stays visible; candidates are NOT capacity-gated so the notice can show). Detach: 1 attached → dropdown, >1 → multi-select with Select-All. `deviceCheckboxList` takes a `limit:` (nil = uncapped, used by adopt/release). The attach response returns `attached: [{device_code, device_type}]` (**added to `openapi-2.1.1-edits.json`'s `DeviceCommandResponseSchema`** — was missing, broke strict decode).
- **collect_resources / deposit_resources** (transport `transport` feature; UI "Load"/"Unload") — **immediate**, no tracked op. Load pulls from the location's `inventory` stockpile into the hold; unload drops back to the location. Body carries a **`resources` object map** `{resource_type: qty}` (an `additionalProperties:number` bag, so built via JSON round-trip like set_directive config — `resourcesSchema` helper). `collect_resources` **requires** a non-empty map; `deposit_resources`'s map is **optional — omit it to empty the entire hold** (what UI "Unload All" does). Device tail carries `cargo_capacity`/`cargo_used`/`cargo` (Device.cargoCapacity/cargoUsed/cargoRemaining/cargoItems). Wired 2026-07-19: `OperationKind.collectResources/.depositResources`, `CommandParams.resources: [String:Int]?`, `DeviceCommand.loadCargo/.unloadCargo`. Load opens a **sheet** (`CargoLoadSheet`, DevicesFeature) that fetches the stockpile via `locationsClient.inventory(at:)` and shows a clamped quantity field per resource capped by `min(available, holdRemaining)`; Unload is an inline confirm. Grid gates: Load on `cargoRemaining>0 && location present`, Unload on `!cargoItems.isEmpty && location present`.
- **affected-device refresh**: the immediate dispatch path in CommandClient now, after reading the targeted device, also reads+ingests every device named in the response's `attached`/`detached`/`adopted`/`released` blocks (`affectedDeviceCodes(in:)`), so moved workers/attachments refresh their status/carrier/controller immediately instead of lagging to the next poll. Covers attach/detach/adopt/release.

CommandClient classifies via `completion(for:)` → {deadline, continuous, enqueued, immediate}; immediate commands skip the optimistic-op lifecycle entirely. `deadlineCommands` set forces `recall`/`search`/`compact`/`unfurl` to deadline despite being no-param. See [[location-sites-endpoint]].
