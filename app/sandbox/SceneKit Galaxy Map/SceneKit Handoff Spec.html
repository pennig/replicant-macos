The one idea that makes the transition work

The galaxy and the star system are not two screens — they are one SceneKit scene at two camera distances. The target star is a single persistent node that exists in both states. Drilling in doesn't load a new scene; it flies the camera to that star while the rest of the galaxy recedes and the orrery assembles around the star that was already there. This is the whole trick, and SceneKit makes it natural in a way the HTML/canvas version could only fake.

01Product model, in one breath

A replicant is a self-replicating von Neumann probe the player commands. She prints and deploys devices (mining drones, forges, FTL relays, surge plates…) across star systems, lives inside a host (vessel / matrix / system hub), and grows a presence across the galaxy. The Star Map is how the player reads and directs that presence at two scales:

  • Galaxy Explorer — a 3D map of nearby systems. At a glance: where I have devices and vessels, which systems are linked by FTL relays, what I've scanned vs. only detected, which hold life, which are resource-rich, where foreign replicants are. Layers add signal to the noise of thousands of stars.
  • Star System — a single system as a live orrery: star, habitable zone, planets and moons on their orbits, the asteroid belt, Lagrange points, stationed devices, and vessels moving in real time along their courses. Click a target to inspect or retarget.

The active worked example is Chamakuy (K2 V, the replicant Sylphrena's home belt). The full cast — names, statuses, device codes — lives in data.js and galaxy-data.jsx and is reproduced as Swift in §3.

HUD material

Every floating panel is one recipe: a dark translucent glass card. In SwiftUI lay the HUD over the SCNView in a ZStack and use .ultraThinMaterial (or a custom .background(.black.opacity(0.62)) + blur) with a hairline inner stroke and a soft drop shadow. HUD is SwiftUI, not SceneKit — only the map itself is the scene.

// HUD glass — SwiftUI, layered above SCNView
extension View {
  func hudGlass(radius: CGFloat = 16) -> some View {
    self
      .background(.ultraThinMaterial, in: RoundedRectangle(cornerRadius: radius))
      .overlay(RoundedRectangle(cornerRadius: radius)
        .strokeBorder(.white.opacity(0.10), lineWidth: 0.5))
      .shadow(color: .black.opacity(0.45), radius: 30, y: 12)
  }
}

Bloom — use the camera, dial it down

The prototype's bloom was too strong because canvas fakes it with additive sprites. In SceneKit, delete that approach: set camera.bloomIntensity ≈ 0.3–0.5, bloomThreshold ≈ 0.8, bloomBlurRadius ≈ 8, and drive glow with material emission on the star spheres. HDR + tone-mapping on the camera gives a far cleaner falloff than sprite stacks. The "bloom" tweak the user tuned to 0.3 maps to bloomIntensity.

Camera rig

One gimbal pattern serves both views and the transition. A pivot node at the look-at point; the camera is a child pulled back along −Z. Orbit = rotate the pivot; zoom = change the camera's local z (or camera.fieldOfView); pan = translate the pivot.

let pivot = SCNNode()                 // look-at point
let camNode = SCNNode()
camNode.camera = {
  let c = SCNCamera()
  c.wantsHDR = true; c.bloomIntensity = 0.35
  c.bloomThreshold = 0.8;  c.bloomBlurRadius = 8
  return c
}()
camNode.position = SCNVector3(0, 0, distance)
pivot.addChildNode(camNode)
pivot.eulerAngles = SCNVector3(pitch, yaw, 0)   // start ≈ (−0.92, 0.5, 0)

Use NSMagnificationGestureRecognizer, scroll-wheel events, and NSPanGestureRecognizer; gate auto-rotate on interaction recency exactly as the prototype does.

Scaling to thousands

Charted systems stay as real nodes (only ~16–100). The ambient field must not be nodes — bake it into a single particle system or point-primitive geometry so 6,000 stars cost one draw call. Add distance LOD if the charted set grows: cull labels by screen-space size (the prototype only shows labels past a zoom/size threshold — replicate that).

05Star System → SceneKit

The user's intent: the system is rendered in the same scene, with the star and planets as true 3D spheres and the orbit rings / HZ band as flat (2D) geometry lying in the ecliptic plane. That hybrid — 3D bodies, 2D orbital scaffolding — is exactly what reads as an orrery.

Orbit motion & the arced courses

Drive orbits with an SCNAction.rotate(by:.pi*2, around:Y, duration: period) repeated forever on each orbit-parent — speed scaled by the same "orbit speed" factor the user tuned (0.05). For courses, the prototype bows the path's control point radially outward from the star so a route never intersects the sun; reproduce that when laying the bezier tube and when interpolating the vessel's position along it.

06The transition — the piece to perfect

Galaxy → system is a single continuous camera move over one scene. The star you clicked never leaves the screen; the galaxy recedes around it and the orrery assembles in place. Reverse to return.

Architecture

Keep one scene. Each charted system node owns a lazily-built orrery child node (rings, planets, belts, HZ), hidden and scaled to zero by default. The galaxy field + all other system nodes belong to a galaxyLayer node. The clicked star's node is promoted to "the sun" — no swap, no reload. SwiftUI HUD cross-fades from the galaxy set to the system set in step with the camera.

Drill in (≈1.15 s, easeInOut)

1

Aim & approach

Move the camera pivot to the target star's world position and reduce camera distance (the prototype's flyTo: zoom 1.18 → ~5.2, recenter on the node). The target star stays dead-center the entire time.

SCNTransaction · animate pivot.position → star.worldPosition, camNode.z → near

2

The galaxy recedes

Fade galaxyLayer opacity 1 → 0 and let the ambient field stream outward with the dolly (parallax does this for free as the camera pushes in). Other charted systems dim and slide past the frame — they don't blink out.

galaxyLayer.opacity → 0 over the back half · field parallax from the dolly

3

The orrery assembles around the star (≈ midpoint)

At ~55% progress, unhide the target node's orrery child and animate it from scale 0 → 1 with opacity 0 → 1: orbit rings and the HZ band fade up first, then planets settle onto their orbits (a short scale-in / ease to position). The same sphere that was a galaxy star is now the sun at the orrery's heart — it visibly grows into a lit 3D body rather than being replaced.

orrery.isHidden = false · scale 0→1, opacity 0→1 · rings before planets

4

Settle

Camera arrives; orbit actions are already running so planets are mid-motion on landing. HUD has finished cross-fading to the system rail, tracked dock, and dossier. Pointer input rebinds to system hit-testing.

onDone → bind system gestures · start/confirm orbit SCNActions

Zoom out (≈0.95 s) — reverse

Retract the orrery (scale 1 → 0, planets fold back toward the star, rings fade), promote the star back into the galaxy field, fade galaxyLayer back to 1, and ease the camera pivot + distance back to the prior galaxy pose. The star is continuous across the whole round-trip. The HUD's ↖ Back to Galaxy button (in the system inset card) triggers it.

Timing & easing reference (from the prototype)

Drill-in 1150 ms, orrery reveal fires at 0.55 of progress. Zoom-out 950 ms, galaxy HUD returns at 0.25. Easing is a symmetric easeInOut (cubic). These are tuned values — start here, then refine on-device where real depth and the lit sphere will let you push the drama further than canvas could.

08Open questions & next steps

  1. Second real system. Only Chamakuy is modeled as an orrery; other scanned systems currently reuse it relabeled. Decide the data source for per-system bodies (procedural seed vs. authored) before drilling into a second star means something.
  2. Unscanned drill-in. Today only scanned/visited systems offer "Drill into system." Define what an aware-only system shows — a sparse "uncharted" shell that fills in as you scan?
  3. Relay color. Amber relays read best on the field but collide with the accent. Confirm amber-in-map vs. the purple StatusRelay token.
  4. Depth of field. SceneKit can add real DoF on the camera during the transition — worth a pass once the sphere is lit; it'll sell the scale far past what canvas allowed.
  5. Inset minimaps. The system view's galaxy inset and a galaxy-view system inset can become live SCNView thumbnails or stay as schematic 2D — cheaper as 2D.
