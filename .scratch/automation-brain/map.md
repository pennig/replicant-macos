# Automation brain — running the fleet unattended

## Destination

The app runs the fleet **without operator intervention.** A standing orchestrator
("the brain") observes global world state and pursues five standing capabilities
autonomously:

1. **Charting** — uncharted systems continually surveyed (survey roam, *shipped*).
2. **Mining** — mining arrives at any discovered salvage/belt site (Salvage Run, *shipped, not running*).
3. **FTL mesh** — **grows *and* prunes**: grows where useful (bridging >7.5 ly gaps by planting relays at boring waypoint systems) and reclaims relays from durably-useless systems to recover rare resources (the `tendMesh` goal, *unbuilt*).
4. **Printing + delivery** — devices print automatically and are delivered where needed (*unbuilt; the `awaitingRelayRestock` human-stall is this hole*).
5. **Location events** — fulfilled with a few clicks + waiting (*unbuilt*).

Everything runs unattended **within a spend ceiling.** Location events are the one
seam that hands control back: the brain surfaces the fulfilment approaches and their
tradeoffs, the operator picks when there's no clear winner, then it executes and waits.

The brain is **additive** — it launches/retires the existing Survey and Salvage runs as
opaque executors and builds only genuinely-new behaviour on `print`/`deliver`/`shuttle`
primitives. **"Done" includes a robustness bar:** B (a global orchestrator) is the
fraught path, so no capability counts as complete until it clears an explicit
anti-fragility standard.

**This map stops at locked designs + handoff-ready plans.** Each capability is then
built in its own subagent-driven session, as every prior Directives stage was. The map
resolves *decisions*; it builds nothing.

## Notes

**Domain.** The automations feature is named **Directives**. It is mature: a clock-driven
(5s tick), per-directive engine (`DirectiveEngine`, non-TCA) over a pure `WorldSnapshot`;
bespoke `MissionStepMachine`s (Survey Run + continuous roam, Salvage Run) dispatched
through a `CommandGovernor` (60/min actions budget, per-device in-flight claim); a
unified Directives surface with stall-resolution verbs and a read-only step timeline.
Read these before any ticket:
- `app/.claude/memory/directives-feature.md` — engine architecture + every shipped stage + invariants.
- `app/.claude/memory/salvage-run-design.md` — the two-kind split, the frontier bootstrap, and **the four threads deliberately-not-built** (engine printing/stowing/repair; tag-driven non-AMI automation; relay+beacon emplacement for events; waypoint relay errands). This effort is largely those threads under one brain.
- `app/.claude/memory/ftl-authority-rule.md` — command authority + why a stationary anchor replicant and relays matter.
- `app/.claude/memory/architecture-review-v3.md` — the V3.9 automation blockers this design answers.
- `app/.claude/memory/travel-is-cheap-vs-survey.md`, `salvage-resource-amounts.md`, `device-tags-and-control-range.md`, `ami-drones-are-event-silent.md` — measured facts the policy layer will lean on.
- Specs/plans live under `docs/superpowers/`; `app/CLAUDE.md` holds the engine + backend-access rules.

**Skills every session should consult.** `/grilling` + `/domain-modeling` (default), `/prototype`
for the primitive/world-model tickets, `/research` for the AFK tickets, `probe-api`
(GET-only is safe; POST/PATCH/DELETE mutate the one live account and must be announced),
`swift-test-event-stream`, and the `pfw-*` skills for engine/TCA patterns.

**Standing preferences for this effort.**
- **Additive, always.** Never rewrite a shipped run to satisfy a purity goal. Re-expressing Survey/Salvage as primitives is a later cheap refactor, out of scope here.
- **Robustness is definition-of-done**, not a phase. Every capability design must state how it clears the bar (ticket 02).
- **Solo-operator.** One operator, ever. Authoring friction is the kill-risk; unattended + a few clicks beats flexibility.
- **Plan-only.** Tickets resolve to designs + plans; builds happen in separate subagent-driven sessions.

- [Research: printing & autofactory](issues/07-research-printing-autofactory.md) — gate = the `print` feature (autofactory: 10-slot queue; the 3 print vessels: single-job); material = a blueprint's six-type `resources` bill drawn from the printer's **location stockpile** (short stock parks the job), `ftl_relay` = 370 units; lifecycle enqueue → `print_complete` (carries `new_device_code`) → **auto-deployed at the printer's location**, optionally adopted/oncomplete.
- [Research: location-event fulfilment](issues/08-research-location-event-fulfilment.md) — an event's `criteria[]` holds fulfilment *options* (devices+resources), `progress` mirrors them live with `met_option`; **the choice is real but a minority (5 of 16 offer alternatives)** and is authored in the payload, not selected by the call — you stage one option on-site, fulfil with an **empty POST** `locations/{code}/events/{designation}` (replicant must be present). Population is a **rare bursty interrupt (~0.5/day)**, so the HITL seam is occasional. Tradeoff axes are device/resource swaps only — never delivery-vs-command or explicit time/cost.
- [Research: delivery & control mechanics](issues/09-research-delivery-control-mechanics.md) — delivery = cradle `stow→travel→deploy→activate` or surge `attach→travel→detach`; authority never hands off per-device — **activating a relay at a system's L4 meshes the system**. **`in_control_range` is the server's authoritative per-device "can I command this now" bool** (already decoded/read by the app) — the brain should read it, not recompute the mesh, and never gate on a carrier's flag. Tags address a fleet account-wide (sees stowed/travelling) but, unlike an AMI controller, pay actions-budget per command. L4 is a first-class travel target (`<STAR>-<n>-L4`).
- [Robustness bar — the definition of done](issues/02-robustness-bar.md) — the acceptance criteria (canonical home: `app/.claude/memory/brain-robustness-bar.md`). **Spine: the brain is a pure *selector* over the existing safe rails** — it ranks goals, never enacts; every command still flows executor → `CommandGovernor` → engine. This absorbs *purity* + *one-enactment-path* + most of *blast-radius*, and reframes 05: **print/deliver/shuttle are new executors, event fulfilment is a *composing* executor, the brain is stateless between ticks.** Eight checkable clauses (selector-not-enactor · stateless · pure-selection/API-vetoes-never-chooses · three-tier snapshot fidelity → *staleness degrades efficiency, never safety* · end-to-end-through-the-real-seam testability · safe degradation with idle-surfaced-not-escalated vs stall-surfaced-and-escalated · bounded blast radius via additive-writes/don't-strand/**rail-enforced spend ceiling** · live derived "why" view + limits-are-signals incl. 429). Every design (03–06) + build plan carries a **Robustness section** answering each, verified in review with evidence. 03 owns the ceiling *value*; 05 inherits don't-strand.
- [Brain ↔ executor seam](issues/04-brain-executor-seam.md) — the brain is an **allocation layer above** the `DirectiveEngine`, touching it through a tiny vocabulary: **create / cancel a directive + drive the sanctioned `retry`/`cancel` resolution verbs**, never enacting, composing, or hand-editing an executor. **Placement:** a nonisolated-ranking plan loop on the existing `DirectiveEngineCore` **actor** (already off-main), race-free via actor + GRDB-serialized writes; output is a manual launch's. **Ownership:** the running **directive rows ARE the lease ledger** (no new lease/table) — reserve by excluding each running directive's `deviceCode`+transitive-stow / `controllerCode` / `fleetTag`, plus in-tick reservation; controller still claimed at preflight; **retire = status-guarded `.cancelled`** (leaves the AMI directive in force). **Feedback:** `status` + `attentionReason` re-read each tick (the stateless memory); the HITL event choice rides `.needsAttention` as a distinguished *decision-request*. **Stalls:** the mission-layer "everything halts" matrix is **unchanged** — the brain adds a response layer classified by `DirectiveAttentionReason.brainDisposition ∈ {retry, escalate, decisionRequest}` (bounded, timeline-derived retry; **auto-skip stays rejected**; auto-retry ≠ auto-skip). **Supply is executor self-composition, never brain-orchestrated** — capability #4 closes because `tendMesh` self-supplies. **Amends 02 clause 1** (brain may drive `retry`/`cancel`). **Contract to 05:** executors expose their committed devices on the row. Canonical: `app/.claude/memory/brain-executor-seam.md`.
- [Goal & decision policy](issues/03-goal-decision-policy.md) — the brain is a **pure selector**: each tick it derives goals from `WorldView`, ranks them with a lexicographic key, and allocates devices/budget via **one greedy pass** (ranking *is* contention resolution). **Five goal kinds** — `survey`, `tendMesh` (**grow + prune**, one worthiness heuristic inverted), `mine`, `salvage`, `fulfillEvent`; `print`/`deliver`/`shuttle`/`repair` are **engines not goals**; `growFleet` reserved-future (needs a fleet-health/supply awareness that also owns orphan-repair). Dependencies are **implicit via derivability** (no cross-goal promoter; downstream value folds into `tendMesh` worthiness). **Two priority axes:** acquisition order (protect-committed → `fulfillEvent` → production → `tendMesh` → `survey`, always-on) vs a **conservative inverted liveness floor** protecting the enabling chain from *deadlock* (repair-priority inverted + resource-reserve floor; the brain prioritizes repair, executors enact it). **Spend ceiling = a per-type resource reserve floor at the enactment rail** (02 clause 7) — ties expansion to production surplus — plus a soft **≤ N idle-relay** anti-hoarding cap (reclaim feeds it → auto-suppresses printing; sprawl is bounded by worthiness, not the ceiling); concrete `R`/`N` calibrate with 06. **Idle** keeps `survey` + the liveness floor running; **backoff is implicit/stateless** (derivability + the row's staleness horizon); idle-calm stays distinct from a stuck-goal stall in the why-view. Canonical: `app/CONTEXT.md` (glossary) + `app/.claude/memory/brain-goal-decision-policy.md`.
- [Primitive contracts: print / deliver / shuttle](issues/05-primitive-contracts.md) — print/deliver/shuttle are **engines** (03's sense), modelled as **step-libraries spliced into ONE composing `MissionStepMachine`** (no lighter tier exists; SalvageRun already inlines deliver+mine) — the brain never touches an engine, it launches an executor that uses them. **Key finding: the engines FIT the existing engine, no mismatch** — `deliver` is SalvageRun's shape (a carrier-owned directive that `.dispatch`es to *other* devices); `print` is one step in it (`enqueue_print(device_type)` at the autofactory — a shared 10-slot queue, **never leased**); they compose into **one carrier-owned Relay Run directive** (the reserved `relayRun` kind) the brain launches for `tendMesh` exactly as it launches Survey Run for `survey`. **Ownership (04's handed question): the carrier `deviceCode` is the ONLY lease** + the relay held via transitive stow → **04's "add a committed-devices field?" = NO**, no new column, no fleet tag. **Contracts:** print (product = a device auto-deployed idle at the printer's location; short-stock→retry/idle, no-printer→escalate); deliver (stow/attach→travel→deploy→**relay: activate in-situ, vessel present**→confirm off authoritative `in_control_range`; transport gated by **don't-strand [02#7]** — surge only to already-meshed targets, a relay MUST stow-aboard; **live-tested: pre-activate-then-move does NOT mesh**); shuttle = **D4 deferred to 06** (collapse into the shipped Haul Run vs distinct). Canonical: `app/.claude/memory/brain-primitive-contracts.md`; runnable artifact `research/05-primitives-prototype.swift`.
- [Resource-hub model](issues/06-resource-hub-model.md) — a hub is a **derived, recognised predicate** (a commandable location with a print-capable device + adequate per-type stock), **not** a placed/managed object — **single hub this effort**, derived from the one autofactory's location, meshed by anchor co-location; placement/multi-hub → `growFleet`-future. **Print-in-situ is dead** (sites ≤3 types, a relay needs 6): printing is **at the hub** with a HEAVEN Vessel co-located to auto-stow. **Inventory:** rank on **per-type wherever known** (`SiteAssay` + retained confirm-reads; totals only as fallback) — a small **additive** per-type stockpile record beyond totals-only `LocationFootprint`; the `.high` per-type `/inventory` read is the `printStockShort` rail veto and is **retained**. **Supply = `mine`/`salvage` ARE the supply line** feeding the hub via the haul engine: salvage = shipped Salvage+Haul Run (sink generalised to the hub), **mine = a dedicated *persistent* Haul Run per site** (never depletes; brain-derived statelessly; separate/decoupled, leased by controller+tag; per-site device cost → `growFleet` trigger). The **Relay Run = print+deliver**, consuming hub stock, **decoupled from resupply through the hub buffer** (`printStockShort` → idle until it fills). **D4 answered — `shuttle` collapses into a generalised Haul Run** (sink → hub; intra-system directive branch), and is the **resupply executor, NOT a Relay-Run co-engine** (**amends 05**; Relay Run engine set = print+deliver only). **Spend ceiling:** `R` = per-type reserve floor rail (expansion-from-surplus), `N` = reclaim-fed idle-relay cap (prune auto-suppresses printing), sprawl bounded by worthiness; literals deferred to build/runtime calibration. **Off-mesh hub → escalate/unsupported.** **Amends 04** (supply-self-composition scoped to the Relay Run) + **03** (`R`/`N` grounded, per-mine-site haul added). Canonical: `app/.claude/memory/brain-resource-hub-model.md`.
- [Mesh-tend worthiness — grow + prune](issues/10-mesh-tend-worthiness.md) — **the last spine decision; the mesh heuristic is one stateless graph computation.** **Structural pivot: `tendMesh` is the SOLE mesh authority** — relay emplacement comes *out* of the Salvage Run, no production goal plants/requests a mesh (**amends the "additive" preference + [[salvage-run-design]]**); the chain is `survey` (mobile, mesh-independent — discovers) → `tendMesh` (meshes ahead of demand) → production (derives only for meshed systems). **Grow = pathfinding toward known value** (salvage + mine + events; survey excluded), ranked `completes-unlock-now → cheapest-chain → [tier ▸ magnitude] → cost → designation`, tier = **Event ▸ Rich belt ▸ Moderate belt ▸ salvage-by-units ▸ Sparse belt** (belt-class is pre-mesh-knowable, yields aren't); **no `critical` flag** (disjoint device sets, **amends 03**). **Prune = the same pathfinding read inversely:** a relay is *useless iff it lies on the cheapest anchor→live-target path-union for nothing* (targets include value only reachable via a chain grow still wants) → **unifies load-bearing + in-progress-hop protection + durable-uselessness**, so a brand-new hop is pinned by construction and **thrash is structurally impossible**. **Reclaim is lazy/demand-driven** — source a needed relay from the nearest useless one before printing (**retires 06's `N` buffer cap**); **no temporal hysteresis**, sole guard is 01's confirm-before-reclaim `.high` read. Canonical: `app/.claude/memory/brain-tendmesh-worthiness.md`.
- [World model & global state](issues/01-world-model-global-state.md) — the brain never holds a fresh-*everything* picture: a derived in-memory `WorldView` (scaled-up `WorldSnapshot`, **no new table**) gives a **best-effort global for ranking** + **just-in-time `.high` confirm at every dispatch** — the shipped `preflight`/`.deferred` pattern lifted to global scope. Event-silent rows (AMI drones) are ranked-on freely but always confirm-read before acting, and the confirm-read *repairs the row it reads* (no staleness tracker). **No new poller, no budget carve-out** — planning rides the SSE drain, dispatches spend the shared `PollCoordinator`, executors own their own freshness; the rule is **exception-free** (location events are SSE-nudged, spend is self-metered, SSE-dropout → inherited gap-repair). Uncertainty ⇒ **defer, escalate if persistent — never guess, never silently hang** (deadlines/UX graduate to 02).
